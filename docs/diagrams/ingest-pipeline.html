Where a batch of events goes, and where it is refused

Game servers post batches, the service validates them, buffers what it accepts, and writes each batch as one multi-row insert. The interesting parts are the two places the request is refused, and the fact that they are refusals rather than failures.

batch size 500 rows · oversized batch 413 · buffer full 503 · accepted batch answered 202 with per-batch counts
Flush on size or on a timer

Because the two conditions fail differently: size alone lets a quiet game's last events sit in memory indefinitely, and a timer alone writes thousands of one-row inserts.

Why one multi-row insert

500 single-row writes are 500 round trips and 500 chances to be slow. The batch is the unit of work because that is the unit the caller already sends.

Where a column store belongs

PostgreSQL is the right shape here. ClickHouse and an orchestrator earn their place when the analytics questions move onto the hot path — the README says where, and this is the line to hold.
